## 1. 它是什么，不是什么

- **是**：从原子 AC 清单与 UX 规范推导出的界面、状态、转移和路径模型，用来决定「要走哪些端到端路径」，由 `pnpm agent -- qa paths` 做确定性校验。
- **不是**：验收规格。规格只在 PRD 的原子 AC 表里；本文件只引用 AC 与 TC，不复制 Given/When/Then。
- 预期结果只来自 PRD、数据字典、UX 规范与 ARCH 接口契约，不以被测系统当前的输出为准。
- 路径由覆盖准则选出；取值差异（等价类、边界值、组合）是同一条路径上的数据行，写进用例的数据集，不新增状态、转移或路径。

## 2. 填写步骤

1. 列界面：每个用户可见的页面或客户端视图一行，写明适用的端。
2. 列状态：每个界面上用户能观察到、且会影响下一步操作的状态（表单待填、提交成功、账号已锁定……）；状态要可断言，不写内部实现细节。
3. 列转移：起始状态 + 操作 + 守卫 → 目标状态；守卫写区分分支的条件，无条件写 `-`。承载验收标准的转移在「关联 AC」里引用该 AC，纯导航转移写 `-`。
4. 选覆盖准则（见第 3 节）。
5. 推导路径：用尽量少的路径覆盖全部转移，路径中的转移必须首尾相接；每条路径绑定一个端到端用例 `TC-{MODULE}-NNN`，与 PRD 原子 AC 表的 TC 列共用同一个编号空间，不得重复。
6. 运行 `pnpm agent -- qa paths`：引用悬空、路径不连通、覆盖缺口、P0 自动化 AC 没有转移承载，都会被列为阻断项。

人工验收（`manual`）的 AC 不需要转移。测试设计技术与预算见 `AgentRoles/Handbooks/QA-TESTING-EXPERT.playbook.md` 的「业务测试自动化」一章。

## 3. 覆盖准则

覆盖准则：all-transitions

- `all-transitions`：每条转移至少被一条路径经过（推荐）；
- `all-states`：每个状态至少被一条路径经过，要求较弱；
- `none`：不要求覆盖，只校验引用；仅用于暂无界面流程的模块，并在评审中说明理由；
- `all-*` 可用逗号组合，`none` 不与其他取值并存，整份文件只声明一次。

## 8. 刷新与评审

- 新增或修改原子 AC 后，先运行 `pnpm agent -- qa paths`，再按缺口补转移与路径；只追加，或把差异作为提案提交评审，不覆盖已评审的界面、状态、转移、路径与用例。
- 标识一经使用不复用；删除或重命名已评审条目前先在评审中确认。
- 被测应用改版导致操作变化时，更新「操作」「守卫」描述，不改标识。
- 驱动自动生成的产物（录制脚本、截图、trace、报告）不进入本文件；报告路径写在 `agent.config.json` 的 `qa.business.suites[].report`，使用相对仓库根、以 `/` 分隔的路径。
