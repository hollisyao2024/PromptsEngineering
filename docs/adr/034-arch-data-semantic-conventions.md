# ADR-034：数据语义约定与 Schema 变更门禁

状态：Accepted。日期：2026-10-03。

## 背景
模型读 schema 理解业务、执行"超时未处理"类提醒与历史分析时，依赖业务化命名、字段注释、审计时间与操作者以及保留的删除历史。现有模板只要求 schema 改动同步 ERD/字典，Drizzle 路径未被识别，也不检查迁移配对、已发布迁移改写与字典覆盖。

## 决策
1. 在 `architecture/standards/data.md` 规定数据语义约定：业务语言 snake_case 命名、表与字段全量注释、状态优先字符串枚举（整数须字典表或注释取值）、六个审计字段、业务表软删除优先并列明豁免与隐私清除。
2. 规定变更流程：schema、新迁移与数据架构文档同一交付；数据库只经迁移文件修改，已发布迁移和快照只追加。
3. `tdd sync` 基于 `architecture.config.json` 登记的存储执行文档同步、迁移配对、只追加和字典覆盖阻断门禁；语义检查默认告警，可配置为阻断。
4. 新生成的 Prisma/Drizzle 任务示例示范全部约定；模块自有与第三方表豁免。生成器检测已安装存储（原 Task 初始迁移或 schema），继续输出 `task-model/legacy` 的原迁移字节、schema 与示例服务，全新存储才在同一迁移 ID 下生成语义 `task`。

## 取舍
门禁以 git 差异和增量迁移 SQL 为单位离线运行，不跑 ORM 或连库，覆盖四种数据库且结果确定；代价是无法证明 schema 与迁移逐项等价，也无法发现绕过迁移的手工 DDL，后续以 `db:status` 漂移检测补充。语义检查先告警，避免一次性阻断已有项目历史表。Prisma 不支持部分索引与列注释声明，示例在迁移 SQL 中补注释、使用普通索引。已有项目的 schema、服务和已发布迁移不被模板改写。

## 依据
模块 ARCH `data-semantics`（息壤源仓已不保留，见 git 历史）；用户 2026-10-03 确认流程类检查阻断、语义检查告警、snake_case、软删除豁免范围与字符串枚举优先。
