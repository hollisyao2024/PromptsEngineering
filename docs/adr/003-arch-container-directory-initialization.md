# ADR-003：容器目录由写入命令按需初始化

- 状态：Accepted
- 日期：2026-08-26
- 关联：US-CMDSURF-005

## 背景

模板默认把 `worktrees`、`tmp`、`cache`、`artifacts` 配置为主 repo 同级目录。目标项目可能只存在 `repo/`；稳定命令首次使用对应目录时不应要求用户预先手工建立，但配置读取、列表和审计等只读操作也不应无条件污染容器文件系统。

## 决策

在共享配置/路径层提供显式容器目录初始化接口。接口只接受 `worktrees`、`tmp`、`cache`、`artifacts` 白名单 key，复用主 repo 根、配置深合并、容器拓扑校验与绝对路径解析，随后递归创建目录并通过 `lstat` 确认目标是实际目录。写入型调用方声明自身所需 key 后才能继续副作用；配置加载和纯路径解析保持无副作用。构建、CI 和发布型项目命令在启动前初始化并传递 `tmp`、`cache`、`artifacts` 的绝对路径。

## 被拒绝方案

- 在 `loadConfig()` 时创建全部目录：实现简单，但所有只读命令都会写文件系统，配置解析不再可预测。
- 由每个调用方自行 `mkdir`：会复制拓扑解析、错误语义和安全校验，容易再次出现 linked worktree 下的相对路径猜测。
- 仅在文档中要求用户预创建：不能满足首次执行自愈目标，也会让自动化因环境准备遗漏而失败。
- 接受符号链接目录：容器状态与产物可能被重定向到边界之外，不符合真实目录与删除安全约束。

## 后果

- 正向：首次缺目录可自愈；重复初始化幂等；目录路径、错误和安全校验保持一致；只读命令无新增副作用。
- 代价：每类写入命令需要显式声明目录需求，新增目录 key 时必须更新白名单与测试。
- 风险控制：覆盖缺失、已存在、文件占位、符号链接、非法 key、创建失败和只读无副作用测试；初始化失败时禁止继续项目命令或状态写入。
