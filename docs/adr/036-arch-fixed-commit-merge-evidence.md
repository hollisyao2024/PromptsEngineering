# ADR-036：固定提交集成证据与严格发布判定分离

- 状态：Accepted
- 日期：2026-10-04
- 关联：US-CMDSURF-015/016，TC-CMDSURF-041~046

项目的历史发布限制可能独立于当前维护提交，但原严格检查不能表达这一区别。继续以 strict 为默认；项目显式配置 fixed-commit 时，session 从有效 QA 回执的固定 base/head 读取 Git blob，对比逐条缺陷/NFR 语义指纹，阻断新增/变化的阻塞、文件删除及无闭环记录删除，同时报告严格发布结论。project 模式继续严格。

选择独立检查组件复用现有解析器，避免改变发布判定；拒绝隐式豁免和可变工作区输入。证据路径为规范仓库相对路径，读取/配置失败阻断；重复来源采用最坏状态。无关行号和全文哈希不参与记录指纹；每条解析语义与来源路径参与。已知边界为现有缺陷/NFR 文档格式，不自动推断项目业务规则。

代价为多读两份 Git 快照，输出上限 32 MiB；没有新依赖、服务、schema 或权限。回滚 revert 并恢复 strict。测试覆盖历史限制保留、恶化、删除、明确闭环、非法路径、重复来源、不可变快照和自动换行环境；Git 夹具在自身提交中声明 LF，命令级配置不修改主机设置。
