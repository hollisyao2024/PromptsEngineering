# 息壤推广方案

[项目首页](../../README.md) · [发布素材](launch-kit.md) · [插件与分发渠道评估](distribution.md)

目标：让目标开发者访问 GitHub、完成首次接入，并在真实任务中继续使用。首轮以验证采用路径为主；Star 是辅助信号，不能代替实际使用。

## 定位与首批用户

主张：面向多人、多 AI 会话并行开发的工程协作模板；通过任务、独立 worktree、验证和恢复约定，帮助团队管理 AI 开发过程。

首批用户优先选择已有 Git 和 AI 编程经验、正在尝试两项以上并行任务的开发者与小团队。先解决“会话互相干扰、任务中断、交付口径不一致”这几个具体问题。架构生成作为后续按需采用能力，避免首次接入同时引入技术栈迁移。

不宣传未经验证的提效倍数、零冲突、全自动开发或所有客户端即装即用。没有实测数据的时间目标只用于内部测量，不写成对外承诺。

## 用户路径

社区中的具体问题 → 真实演示或技术文章 → GitHub README → 快速接入 → 双任务演练 → 实际项目采用 → 反馈和贡献。

首页首屏回答是什么、解决什么、适合谁、如何开始；技术参考保留升级、所有权与恢复细节。每篇推广内容只引导一个下一动作：首次接入，或复现一次并行协作。

## 四周执行顺序

以下按工作顺序安排，不是已经发生的试用或发布记录。

| 阶段 | 交付 | 放行标准 |
| --- | --- | --- |
| 第 1 周：补齐入口 | 中英文首页、快速上手、协作教程、贡献说明、原说明参考页 | 干净目标完成接入与收敛预演；文档链接、契约检查通过 |
| 第 2 周：小范围试用 | 邀请 5 位目标开发者独立试用；记录卡点并修复 | 目标至少 3 人不需作者代操作完成接入；所有失败均能定位。数值是实验目标，不是已有结果 |
| 第 3 周：发布真实案例 | 一篇中文实操文章、一段实际录屏、一份可复现案例 | 读者能找到相同命令与结果；证据脱敏；所有功能属于已交付范围 |
| 第 4 周：扩大分发 | 英文案例、相关社区分享、自建插件市场适配评估 | 按来源比较采用反馈；若上手卡点未修复，暂停扩渠道，先修路径 |

插件适配属于后续实现范围，见[分发路线](distribution.md)。录屏和用户试用需要真实执行，不能用脚本或文案冒充已完成。

## 渠道优先级

| 优先级 | 渠道 | 内容与目的 |
| --- | --- | --- |
| P0 | GitHub | README、Issues、版本记录；作为代码、教程和证据的主源 |
| P1 | 已有开发者圈、AI 编程与工程团队 | 小范围邀请试用，找接入卡点；由维护者主动联系，先征得对方参与意愿 |
| P1 | 掘金、知乎或个人技术博客，选一个主阵地 | 发布一个双任务实操案例，持续修订，不同平台不机械群发 |
| P1 | B 站等视频平台，选一个 | 录屏展示任务 → 两个 worktree → QA → 合并和一次受控失败 |
| P2 | Claude Code 自建插件市场 | 经适配和验证后降低安装成本；GitHub 仍保留完整协议与工具 |
| P2 | ChatGPT/Codex 公共插件目录、Claude 官方市场 | 完成产品化打包与试用后申请收录，审核通过不等于保证流量 |
| P3 | 英文技术社区、相关 curated/awesome 清单 | 有英文说明与复现案例后提交；逐个核对相关性与投稿规则 |

这些是待验证的渠道选择，不是流量排名。发布当日核对社区自荐规则；外部发帖、私信、投稿、市场提交和账号设置变更由维护者明确授权后执行。

## 测量方式

| 阶段 | 指标 | 如何获取与解释 |
| --- | --- | --- |
| 触达 | 仓库独立访客、来源、clone 趋势 | GitHub Traffic；是发现信号，不是安装人数 |
| 接入 | 独立完成接入人数、耗时、失败步骤 | 试用者自愿反馈；从开始命令到收敛预演，记录环境与是否需作者介入 |
| 激活 | 完成一项真实任务及 QA/合并的人数 | 以可公开 PR 或用户自述区分；演练和生产项目分开统计 |
| 留存 | 一周后是否继续使用、是否有第二项任务 | 自愿回访；不加隐性遥测，不上传项目状态 |
| 传播 | 真实案例、Issue、贡献和 Star 趋势 | 结合来源与采用反馈评估，不把 clone/Star 当作使用量 |

GitHub Traffic 只提供近 14 天访客与 clone 等信息，按周导出或人工记录；不能据此精确归因每篇帖文，更不能计算“clone 到安装”的真实转化率。[GitHub Traffic 文档](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository)

每周复盘：哪些人接入了、卡在哪、什么内容带来可验证反馈。先修最大的采用阻力，再决定扩大渠道；不在未测量时设置虚构基线或展示增长图。

## 本轮与后续边界

本轮仓库交付是文档、教程和待发布素材。真实录屏、5 人试用、账号设置、外部发帖、插件代码与市场审核分别验证，不因文档已合并而自动宣称完成。
