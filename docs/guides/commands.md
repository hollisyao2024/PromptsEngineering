# 常用指令速查

[首页](../../README.md) · [English overview](../../README.en.md) · [快速上手](quickstart.md) · [并行协作](parallel-collaboration.md) · [完整参考](template-reference.md)

这些是发送给 AI 的自然语言指令，不是终端命令或所有客户端都注册的斜杠命令。AI 须能读取本地规则、操作项目文件并运行仓库工具。息壤不绑定单一模型；Claude Code、Codex、Gemini CLI 的入口材料不代表所有客户端、版本与权限组合均已验证，先完成[工具接入检查](quickstart.md#工具接入检查)。

| 你想做什么 | 在哪里说 | 可以直接发送 | 执行范围 |
| --- | --- | --- | --- |
| 首次接入新目录或已有代码库 | 息壤源项目的 AI 会话 | 初始化项目，路径为 `C:\Projects\MyApp\repo`。 | 检查 → 预演 → 安装作业包文件 → 读取生成规则 → 复查；不操作目标 Git |
| 更新已接入的模板 | 对应实际项目的 AI 会话 | 更新息壤模板。 | 明确当前项目绝对路径 → 更新任务与独立 worktree → 固定 GitHub 官方 main 同步 → 验证、QA、合并 |
| 只检查，不修改 | 相应项目的 AI 会话 | 只读检查息壤接入状态，列出缺少的配置，不修改文件。 | 只读核查，不创建任务、worktree或自动修复 |
| 多人多机协作 | 各自电脑中同一项目的 AI 会话 | 执行任务 `<唯一任务ID>`：仅修改 `<文件范围>`，验收为 `<可观察结果>`。按项目规则使用独立 worktree，验证后完成 QA 与合并。 | 各自登记任务、隔离分支与工作区；共享接口先约定，远端 SHA 复验后交付 |
| 单机多任务并行 | 同一电脑上的不同 AI 会话 | 分别按并行教程执行任务 A 和 B，各用独立任务 ID 与 worktree，不写对方文件。 | 每个会话独立开发与验证，不自动分配运行资源或调度其他会话 |
| 多模型接力 | 已完成交接的接手会话 | 接手任务 `<任务ID>`，worktree 为 `<绝对路径>`。先读取基础规则和交接胶囊，核实工作区及未确认的副作用，再按状态恢复。 | 同机已有状态可 resume/context；原执行器停止写入后接手，不重复推送或合并 |

并行指令需给每个会话提供自己的任务 ID、具体文件范围与验收，完整示例见[并行协作教程](parallel-collaboration.md)。模型接力继续同一任务；多人或多会话并行使用独立任务。worktree 隔离文件和依赖目录，不能隔离端口、共享服务、数据库或测试数据；共享接口与锁文件仍需约定负责人和合并顺序，不保证零冲突。

跨电脑接手不会通过 Git 自动同步任务状态、胶囊、未提交内容、本机锁或 QA 回执。先提供交接证据并按本机任务门禁登记或恢复任务，再恢复对应远端工作分支；换电脑合并必须重做本机 QA，不能把“接手任务”理解为自动下载状态。详见[恢复边界](template-reference.md#模型接力与跨电脑恢复)。

## 初始化项目

“初始化实际项目”与“初始化项目”含义相同；提供目标路径即可，推荐使用绝对路径。

- 不存在的独立路径可创建为空目录；已有空目录可直接安装。
- 只安装清单规定的文件，保留模板更新基线；不整仓复制。
- 不执行目标的 Git 初始化、暂存、提交、分支/worktree 创建、远端配置或推送；不在目标创建任务记录。
- 已有 Git 仓库也可初始化，有无提交均不阻断；非空目录按文件所有权和预演结果处理，不要求目标 worktree。已有息壤接入痕迹先核实状态，冲突不覆盖。
- 文件安装成功且复查收敛，即完成本次初始化。Git 开发准备、技术栈和业务代码另行安排。

复用命令是源中的 `pnpm agent -- template update "<目标绝对路径>" --scope agent --initialize`，安装前后各做 dry-run。完整步骤见[快速上手](quickstart.md#让-ai-自动初始化)，执行边界见[源专用初始化协议](source-initialization.md)。完整初始化指引和源专用索引均不分发到实际项目。

## 更新息壤模板

打开要更新的实际项目，再发送“更新息壤模板”。当前已核实的项目就是唯一目标；AI 先明确其绝对路径，目标不明确就先澄清，不猜测或遍历其他项目。无需提供本地息壤源路径。在息壤源项目说这句话时，只提示切换到对应实际项目，不执行跨项目更新。

AI 按当前项目规则登记或恢复任务，创建专用 worktree，在 `NEXT_CWD` 执行 `pnpm agent -- template sync`，再完成验证与交付。来源固定为 [GitHub 官方息壤仓库](https://github.com/hollisyao2024/PromptsEngineering) 的 `main` 分支，获取执行时最新提交并锁定 SHA，不传替换来源的参数；配置偏离官方来源时 CLI 阻断。按版本基线和所有权更新作业包及已采用架构模块，保留项目自有规则、配置和业务代码；冲突、未知基线或获取失败时停止，不回退本地副本或缓存。

“更新项目”可能指业务代码、依赖或模板，不能作为无条件快捷指令。上下文已明确是息壤模板更新时可识别，否则 AI 先澄清。建议直接使用“更新息壤模板”。两种流程的对比见[初始化与更新](quickstart.md#初始化与更新有什么不同)。

## 指令约定放在哪里

用户从 README 的“常用指令”进入本页；本页集中维护说法、参数、执行位置与范围。源的 `AGENTS.md` 引用初始化协议，分发时剔除这条源专用索引；实际项目的更新协议放在 `docs/CONVENTIONS.md`。新增或修改指令时同步对应入口，不向实际项目分发源专用说明。
