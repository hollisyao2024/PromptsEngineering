# 常用指令速查

[首页](../../README.md) · [快速上手](quickstart.md) · [完整参考](template-reference.md)

这些是发送给 AI 的自然语言指令，不是终端命令或所有客户端都注册的斜杠命令。AI 须能读取本地规则并运行仓库工具。

| 你想做什么 | 在哪里说 | 可以直接发送 | 执行范围 |
| --- | --- | --- | --- |
| 初始化空白项目 | 息壤源项目的 AI 会话 | 初始化项目，路径为 `C:\Projects\MyApp\repo`。 | 检查 → 预演 → 安装作业包文件 → 读取生成规则 → 复查；不操作目标 Git |
| 更新已接入的模板 | 对应实际项目的 AI 会话 | 更新息壤模板。 | 明确当前项目绝对路径 → 更新任务与独立 worktree → 固定 GitHub 官方 main 同步 → 验证、QA、合并 |
| 只检查，不修改 | 相应项目的 AI 会话 | 只读检查息壤接入状态，列出缺少的配置，不修改文件。 | 只读核查，不创建任务、worktree或自动修复 |

## 初始化项目

“初始化实际项目”与“初始化项目”含义相同；提供目标路径即可，推荐使用绝对路径。

- 不存在的独立路径可创建为空目录；已有空目录可直接安装。
- 只安装清单规定的文件，保留模板更新基线；不整仓复制。
- 不执行目标的 Git 初始化、暂存、提交、分支/worktree 创建、远端配置或推送；不在目标创建任务记录。
- 已有 Git 仓库、息壤接入痕迹或非空目录会报告对应方案，不凭这条指令自动进入已有项目接入或升级。
- 文件安装成功且复查收敛，即完成本次初始化。Git 开发准备、技术栈和业务代码另行安排。

复用命令是源中的 `pnpm agent -- template update "<目标绝对路径>" --scope agent`，安装前后各做 dry-run。完整步骤见[快速上手](quickstart.md#让-ai-自动初始化)，执行边界见[源专用初始化协议](source-initialization.md)。完整初始化指引不分发到实际项目；共享 `AGENTS.md` 只保留按源角色加载的索引。

## 更新息壤模板

打开要更新的实际项目，再发送“更新息壤模板”。当前已核实的项目就是唯一目标；AI 先明确其绝对路径，目标不明确就先澄清，不猜测或遍历其他项目。无需提供本地息壤源路径。在息壤源项目说这句话时，只提示切换到对应实际项目，不执行跨项目更新。

AI 按当前项目规则登记或恢复任务，创建专用 worktree，在 `NEXT_CWD` 执行 `pnpm agent -- template sync`，再完成验证与交付。来源固定为 [GitHub 官方息壤仓库](https://github.com/hollisyao2024/PromptsEngineering) 的 `main` 分支，获取执行时最新提交并锁定 SHA，不传替换来源的参数；配置偏离官方来源时 CLI 阻断。按版本基线和所有权更新作业包及已采用架构模块，保留项目自有规则、配置和业务代码；冲突、未知基线或获取失败时停止，不回退本地副本或缓存。

“更新项目”可能指业务代码、依赖或模板，不能作为无条件快捷指令。上下文已明确是息壤模板更新时可识别，否则 AI 先澄清。建议直接使用“更新息壤模板”。两种流程的对比见[初始化与更新](quickstart.md#初始化与更新有什么不同)。

## 指令约定放在哪里

用户从 README 的“常用指令”进入本页；本页集中维护说法、参数、执行位置与范围。共享 `AGENTS.md` 保留按角色加载的轻量路由；源专用初始化协议放在 `docs/guides/source-initialization.md`，实际项目的更新协议放在 `docs/CONVENTIONS.md`。新增或修改指令时同步对应入口，不向实际项目分发完整初始化指引。
