# 息壤插件执行边界

本插件是入口适配。实际项目的 AGENTS.md、docs/CONVENTIONS.md、RULES.md 和 CLI 决定任务、worktree、验证与交付；插件不保存第二份状态，不替代宿主权限。

## 定位与能力

先用文件工具确认用户目标目录与 Git 根。已接入项目先按 UTF-8 全文读取三份基础规则至末尾，再执行项目操作；官方源 origin 确认为 hollisyao2024/PromptsEngineering 且 RULES.md 不存在时才免读它。缺失、空或读取失败均按项目规则处理。

需要确定项目形态时，可用包内 `scripts/inspect-project.cjs --project "<目录>"`：从当前技能目录向上两级是插件根。使用解析后的绝对脚本路径，目标路径作为独立参数传入。它只读文件、Git 元数据与入口声明，不运行项目代码、不读 .env.local、不联网；不是完整兼容性或基线哈希验证。

| 返回 | 含义与下一动作 |
| --- | --- |
| UNMANAGED | 未发现息壤标记；只有明确接入请求才进入安装路径 |
| READY | 基础规则、入口与基线存在；仍须加载规则、执行项目门禁 |
| SOURCE | 已识别官方模板源；业务任务应在实际项目执行 |
| INCOMPLETE | 规则/配置/入口/基线有缺口；报告 problems，不写默认规则冒充修复 |
| NEEDS_GIT | 已有模板文件但未取得可用 Git 仓库；检查 Git 与仓库状态，不盲目重新初始化已有仓库 |

探测器仅辅助定位。无 shell/Node/Git 或无项目文件访问时，明确缺少能力，提供下一步；不要声称运行了命令。用户让“看一下”只授权只读诊断。

## 首次接入的模板来源

插件不捆绑模板源码或 updater。使用用户已有、可核实的官方源目录；若尚无源码，在用户选定的独立目录按当前环境权限获取官方公开 HTTPS 源 `https://github.com/hollisyao2024/PromptsEngineering.git`。遵守已有项目的 GitHub 鉴权约定，不从插件读取或索取 token，不改全局 Git/代理配置。

核对源 origin、息壤身份与当前 commit，读取源的基础规则，再调用源自身 updater。无法获取或核实来源时报告缺口，不退回插件内缓存或随手复制文件。目标空目录与已有 Git 项目的初始化边界不同：已有项目必须先遵守自身规则准备专用 worktree。首次初始化缺失规则的例外不适用于已有空规则或读取失败。

已有用户明确接入/更新授权时，核对 dry-run 后继续其范围内的应用与验证，不重复要求同一批准。冲突、范围变化或真实能力缺失则先解决，不以放宽权限推进。

## 执行与恢复

- 先明确可观察验收，再创建或恢复 mutation 任务与 worktree。只读状态查询不触发写入型入口。
- 副作用由项目任务状态记录；命令返回未知时先核实，规则明确拒绝时不换入口重试。
- 命令在输出的真实 NEXT_CWD 中运行；用户文本与路径不要直接拼成可执行 shell 内容。
- 项目定向测试、阶段切换、QA、合并与完成门禁仍由项目规则执行。插件安装、模板接入、业务验证、公共市场发布是不同结果。
- 不修改个人全局配置、自动授予权限、安装远程服务、发送消息或开启遥测。需要此类动作时回到用户的明确范围与当前环境权限。

## 初次试用的四种提示

“给这个项目接入息壤，先展示变更范围。”

“用息壤启动任务 demo-a，只新增一个说明文件，先明确验收。”

“恢复息壤任务 demo-a，核实上次推送的结果再继续。”

“只读检查 demo-a 的交付条件，列出缺少的证据。”

同时测试普通问答不误触发、任务多候选不猜选、无 shell 不假执行，以及检查模式不合并。示例不是已运行的用户试用记录。
