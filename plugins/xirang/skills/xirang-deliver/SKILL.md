先读[共同执行边界](../../references/workflow.md)，完整加载目标项目的基础规则。

**检查模式**：用户只要求核查、解释或状态时，读取 task context、工作区、diff、PR/回执和现有验证证据；不创建任务、不调用写入型 resume、sync、push、merge 或 finish。发现缺少证据就报告缺口，不能把“目录存在”当测试通过。

**交付模式**：用户已要求实现并交付或明确要求完成流水线时，按任务状态继续授权范围。复核完整 diff 和受影响消费者，运行最小充分验证并绑定当前 head，按项目规定依次执行 `tdd sync → tdd push → qa plan → qa verify → qa merge`。使用稳定的 `pnpm agent --` 入口；保持项目规定的阶段转换和证据记录。

合并前核对固定 base/head 与 QA 回执，漂移后重新同步和验证，不自动覆盖远端。用户要求只建 PR 或不合并时尊重该边界。仓库没有远端权限时报告未完成的交付项，不伪称已推送。

合并后在主 worktree 核对本地/远端主干、工作区与适用 completion guard，完成步骤和验收后关闭本任务。主干合并、远端推送、生命周期清理分别报告。除非已有明确发布授权，不将代码交付扩展成部署、市场提交或外部发帖。
