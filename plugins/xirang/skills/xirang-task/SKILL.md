---

先读[共同执行边界](../../references/workflow.md)，完整加载目标项目的基础规则。尚未接入、规则不完整或 CLI 不兼容时说明具体缺口，不能悄悄安装模板或用插件规则替代项目规则。

将用户目标转成可观察验收，明确本任务文件/业务边界、共享接口依赖和最小验证。可从仓库确认的信息自行读取；会改变产品行为的实质歧义先澄清。不要宣称独立 worktree 能消除业务冲突。

检查用户是否正在继续已有任务；已有明确任务 ID 时走恢复入口，避免重复 start。新 mutation 任务使用 `pnpm agent -- task start` 登记显式验收和 safe/verify-first 步骤；生命周期副作用前记录 running。

按项目路由选择阶段，再执行 `pnpm agent -- worktree new --phase=<当前阶段> --task <任务ID>`。创建成功后检查输出的 `NEXT_CWD`，切换到该精确路径；后续编辑、测试、提交全部在那里执行。依赖通过该 worktree 自身的 bootstrap 建立，不跨 worktree 共享 node_modules。

继续用户授权的实现与交付，不停在创建目录。需要并行工作时先明确各任务的依赖与所有权；是否可调用其他代理遵循当前运行环境与用户授权，插件不自动启动额外代理。
